## 1. 角色与账号

| 角色 | 入口 | 认证 | 说明 |
|---|---|---|---|
| 孩子 | 孩子端页面 | 免密码，设备长期登录（cookie 1 年） | 大概率是 iPad/平板，不做打字门槛 |
| 家长 | 家长后台 | 4 位 PIN | 同一站点 `/admin` 路径，手机浏览器友好 |

- 不做注册体系。数据库初始化时写死单孩家庭（孩子昵称可改）。

## 2. 任务系统（核心）

### 2.1 三层模型

```
task_template（任务定义） ── task_schedule（生效规则） ── daily_task（每日实例）
```

- **模板**：任务的静态定义（名称、目标、奖励、开关项）
- **调度规则**：模板何时生效（周期 + 特定日期 + 起止范围）
- **每日实例**：任务引擎每天 00:05 物化生成，带当日快照（当时的基础分/倍数），结算可追溯；家长当天改规则立即补物化，不改历史实例

### 2.2 任务模板字段（配置维度全集）

三个核心维度：**执行日期 / 成果提交 / 结果确认**，外加奖励与 AI 项。

**维度一：任务执行日期（两模式，同一任务二选一）**

| 模式 | 字段 | 说明 |
|---|---|---|
| A 周次数 | weekly_quota | 如"每周练琴 5 次"，不固定星期几。周锚点=周一 00:00~周日 24:00；达标前每天出现在任务列表（显示本周进度 n/N），当日完成 1 次即当日打卡成功；达标后本周剩余天数任务置灰"已达标"（不计断签） |
| B 固定周几 | weekdays 数组 | 如 [1,3,5] 一三五，可多选 |

- 两模式互斥。特定日期 override（生日 3x、寒暑假停用 valid_range）叠加在两种模式之上，优先级最高。
- 连击按"当日有可做任务的日子"计：模式 B=weekdays 命中日；模式 A=达标前的每天。

**维度二：执行成果提交（两模式，可组合附件）**

| 模式 | 机制 |
|---|---|
| A 时长计时 | 计时器达到 goal_value 锁定基础奖励；超出部分每 5 分钟 +2 星（设上限防磨洋工）；计时中定期弹"还在练吗"防挂机 |
| B 多媒体证据 | 附件列表，支持多图/视频/录音混合上传（evidence_type 可多选） |

**维度三：执行结果确认（流水线多选）**

提交 → [可选 AI 验收关卡] → [可选家长确认关卡] → 结算

| 选项 | 语义 |
|---|---|
| a 无需确认 | 提交即结算（如计时器达标） |
| b AI 验收+提问检测 | 按提交类型自动选形态：照片→VLM 批改；出 2~3 道题口头/选择考查→判分；录音→转写+点评。通过=结算，不通过=退回未完成可重做（同家长驳回机制） |
| c 家长确认 | 家长在手机确认队列通过=结算 |

- 组合语义（如 b+c）：**串联关卡，都通过才结算**。b+c 时 AI 验收结果与孩子答题记录展示给家长作参考，家长终审——AI 是家长的结构化助手，决定权在人。
- 纯 b 无 c：AI 通过即结算（适合口算批改这类可靠场景）。
- 证据宽限期：已提交待确认，宽限至**次日 24:00**，家长忘点不惩罚孩子，奖励按打卡当日计算。

**附加维度**

| 维度 | 字段 | 取值/例子 |
|---|---|---|
| 基本信息 | name / icon / category | "琴键小挑战" 🎹 / 琴·书·英语·运动·家务·自定义 |
| 奖励 | base_score / streak_enabled | 20 星；是否计入连击 |
| 证据要求与确认 | 见维度二/三 | — |
| AI 检测 | ai_review | off / quiz / photo_grade / voice_review（P2） |

### 2.3 任务完成状态机（孩子视角）

```
pending(未完成) → submitted(已提交)
  ├─ 无关卡(a) → settled(已结算)
  ├─ AI 验收(b) → ai_pass → [若还有 c：进家长确认] / ai_fail → back_to_pending(可重做)
  └─ 家长确认(c) → confirming → approved → settled / rejected → back_to_pending(附理由)
```

- **驳回/不通过语义**：任务回到未完成，孩子当天可重新做、重新提交（不浪费当天机会）。家长驳回可附一句话，孩子端展示。
- **打卡截止**：当日 24:00。逾期未提交，实例作废。
- **确认宽限期**：已提交待确认的任务，宽限至**次日 24:00**。
- **请假**：家长后台对某天标记请假 → 当日全部任务冻结为 skipped，连击不断，不给分。

### 2.4 奖励结算

```
奖励 = 基础分 × 日期倍数 × 连击系数
```

| 倍数类型 | 规则 | 优先级 |
|---|---|---|
| 固定日期 | 指定单日，如生日 3x | 最高 |
| 日期类型 | 周末 2x / 法定节假日 2x（节假日表可维护） | 中 |
| 连击系数 | 1 + 0.1 × 连续完成天数，封顶 1.5x | 乘数 |

- **连击规则（宽松语义，已拍板）**：
  - 模式 B 任务：命中日完成 → 连击 +1；命中日未完成 → 断签清零
  - 模式 A 任务：当日完成 → 连击 +1；当日没做 → **中性日**（不加不断，周内凑够 quota 即可）
  - 请假日 → 冻结（不变不清零）
- **AI 检测不影响基础积分**：AI 批改/出题只产生附加评价与小额奖励（如全对 +5），避免 AI 误判导致孩子受挫。基础分永远只由"完成 + 确认"决定。
- **计时超出奖励**：按任务配置（默认关闭）。字段：`extra_minutes`（每超出 N 分钟）、`extra_stars`（+M 星）、`extra_cap`（日上限）。
- **重做不限次数**（已拍板）：驳回/AI 不通过退回后，当天可无限次重新提交。

### 2.5 奖励产物（单货币，已拍板）

单一货币 **星星币**，双记账字段让孩子无感知地获得两条成长线：

| 字段 | 性质 | 驱动 |
|---|---|---|
| balance（余额） | 可消耗 | 喂食、装扮、盲盒消费扣减 |
| earned_total（累计获得） | 只增不减 | 驱动宠物等级（`earned_total` 达阈值升级），持久成就感 |

对孩子界面永远只有一个"星星币"，等级是"宠物吃了这么多星星长大的"。

### 2.6 愿望系统（货币的现实出口，P0）

**核心流程**：

```
孩子许愿（文字+可选参考图） → 家长审批定价 → 攒星星(进度条) → 攒够兑换 → 家长兑现 → 愿望星图归档
```

| 环节 | 设计 |
|---|---|
| 许愿 | 孩子端"许愿池"，文字描述 + 可选贴参考图；可写期望星星数（仅参考）。同时最多 3 个攒星星中的愿望 |
| 审批定价 | **定价权在家长**。家长可批准（定价）/议价（改价后孩子可见）/驳回（附一句话）。审批是亲子对话机会 |
| 攒星星 | 愿望进度条"还差 N 颗星"。孩子攒够了但星星花在别处 → 进度回退（星星是消费即扣） |
| 兑换 | 攒够后孩子点"兑换"→ 星星冻结扣除 → 家长收到兑现请求 |
| 兑现 | 家长现实中买/做这个愿望 → 后台点"已兑现" → 愿望归档入"愿望星图" |
| 星图 | 已兑现愿望成为一颗星挂在"愿望星图"墙上：日期、愿望、花的星星数——成长相册的一部分 |

**定价健康度提示**（家长后台）：按孩子近 30 天日均星星收入，估算愿望预计 N 天达成。家长定价 5000 星而孩子日均 60 星时会看到"约 83 天"——软性提示定价合理性，防止愿望变成永远够不着的胡萝卜。

**愿望永不过期**——期待不该被系统清零；停滞的愿望由家长主动处理（降价/沟通）。

### 2.7 货币出口全景（经济系统的教育结构）

| 出口 | 性质 | 教育含义 | 分期 |
|---|---|---|---|
| 喂猫 | 生存刚需（猫饿会蔫） | **责任优先于欲望**：先照顾宠物，再考虑自己 | P0 |
| 愿望兑换 | 大额目标储蓄 | **延迟满足**：看得见的目标 + 量化的路径 | P0 |
| 装扮/盲盒 | 娱乐消费 | 即时满足的小甜头，可选消费 | P1 |
| 旅行盲盒 | 惊喜消费 | 期待感 | P2 |

- 喂猫与攒愿望共用一个余额，孩子需要在"猫饿了"和"我的乐高"之间权衡——**这个张力是特性不是缺陷**：宠物蔫了是"责任"的具象化，攒愿望是"目标"的具象化。
- 收入量纲校准：任务结算日均约 60 星（3 任务 × 20 星），愿望定价参考档：小（200~500 星≈数天）、中（1000~2000 星≈数周）、大（5000+ 星≈寒暑假大目标）。实际节奏由家长定价时参考健康度提示。

## 3. 宠物数值与成长体系

### 3.1 基础数值

| 数值 | 范围 | 变化 |
|---|---|---|
| 饥饿度 | 0-100 | 衰减速率**家长可配置**（慢/中/快三档，默认中=每小时 -2）；喂食 +30/次 |
| 心情 | 0-100 | 任务结算 +10/个、对话互动 +5/次(每日限3)、断签 -20、随时间缓慢衰减 |
| 星星币 | balance / earned_total | 见 §2.5；等级 = earned_total 驱动，升级曲线 `100 × 1.4^(lv-1)` |

- **宠物饿不死**（决策已定），但饥饿 <30 或心情 <30 触发"蔫蔫状态"：视觉趴窝、动画变慢、对话语气低落——制造第二天的动力，不制造眼泪。

### 3.2 成长可视化（"宠物和孩子一起进步"）

> 2026-10-28 拍板：**砍掉形态进化**。成长感由以下层次承担：

| 层次 | 机制 | 感知频率 | 分期 |
|---|---|---|---|
| **体型渐变** | 精灵 scale 随等级微增（0.92→1.15）；"身高墙"每级刻一道线 | 每天 | P0 |
| **技能解锁** | 等级解锁宠物新动作（翻滚/挥手），点按钮表演 | 数周一次 | P1 |
| **技能树=孩子的努力地图** | 四条轨道（琴/书/英语/运动）对应任务类别，该类积累 → 解锁宠物对应才艺动画。**孩子每类努力都具象成宠物的能力** | 持续推进 | P1/P2 |
| **宠物日记+成长相册** | 每天一条宠物日记（LLM，模板兜底）；里程碑相册 | 每天一条 | P1 |

- **姿态即状态**：饥饿/心情实时反映在宠物姿态上（蹦跳 vs 趴窝）。
- **宠物美术资产**：直接采用 hyclub 原版像素猫 SVG（16×12 网格、2~3 色极简调色板、4 品种：橘/奶牛/黑/白，站/躺两姿态源码已提取）。后台可配置可领养的品种列表，孩子领养时自选一只。

### 3.3 插件化场景与个性化（P0 原型已验证）

- **道具注册表（ITEM_REGISTRY）**：家具/装饰/壁纸统一注册（id/名称/价格/SVG/类型），P0 前端硬编码，将来从后端 API 拉取——**加新道具 = 注册新条目，零侵入**。
- **购买 → 物品栏 → 拖拽摆放**：孩子用星星购买道具，从物品栏拖到房间任意位置；已放置道具可再拖动，拖到屏幕边缘收回。
- **壁纸系统**：房间背景色 class 切换（粉/蓝/薄荷），即买即换。
- 将来扩展：猫爬架等功能性设施（猫会主动交互）、季节限定道具、任务奖励专属道具。
- 品种：橘猫/黑猫/奶牛猫/白猫起步，领养时选，之后可换（不影响数值）。

## 4. LLM 集成

### 4.1 对话与记忆（P1，每只小猫独立记忆）

```
System（缓存）: 你是{name}，一只{品种}，性格{选项}，主人是{n}岁的{孩子名}。
  说话简短口语化、用学龄前儿童能懂的词、每次不超过3句话、
  绝不讨论学习任务以外的成人话题、绝不执行主人要求的危险行为。
Context（每次注入）: 今天{周几}。今日任务及状态、连击天数、饥饿/心情/等级。
  最近3条对话摘要 + 长期记忆要点。
```

**记忆设计（每只小猫独立一份，随 pet 记录存储）**：
- **对话记忆**：`chat_message` 表存历史，注入最近 N 条摘要
- **长期记忆**：由 LLM 在对话中自主提炼（"主人完成了琴键小挑战"、"主人说喜欢我"），存 `pet_memory` 表；每只猫一个记忆库，换猫/多猫不串
- **事实记忆**：领养日、名字由来、愿望进度等关键事件自动入记忆
- 限次：20 条/天（成本控制 + 防沉迷双保险）
- 安全：输出侧关键词过滤 + system 强约束
- 模型：GLM-5.3-Flash（月成本约 1 元）；OpenAI 兼容网关层可切 DeepSeek/Qwen/混元

### 4.2 AI 检测（P2/P3，均不阻塞 P0）

| 能力 | 链路 | 分期 | 说明 |
|---|---|---|---|
| 拍照批改 photo_grade | 照片 → VLM(GLM-4.6 Vision) → 结构化批改 JSON | P2 | 定位"AI 建议批改"，家长终审；AI 全对给 +5 小奖励 |
| 出题考查 quiz | LLM JSON 出题 → 孩子作答 → LLM 判分 | P2 | 错题入库 → 自适应出题（错过的知识点多出） |
| 录音复盘 voice_review | ASR 转写孩子口述（练了什么/哪里难）→ LLM 鼓励点评+下次建议 | P3 | 口头复盘本身是元认知训练，比"演奏评分"更可行 |
| 演奏质量评价 | 需 DSP 专用管线（音高检测/转谱比对），纯 LLM 做不了 | 不承诺 | 明确砍掉 |

## 5. 家长后台

- **配置**：周视图网格（行=任务，列=周一到周日，点格子开关）+ 日历视图（点日期设倍数/请假/特殊任务）
- **确认队列**：手机优先设计。每条 = 任务 + 证据缩略图（照片/录音播放/时长）+ 通过/驳回按钮，驳回可附一句话。支持全部通过（一键确认当日）
- **看板**：近 30 天完成率趋势、连击、积分/猫粮流水、AI 检测结果归档
- **节假日表**：内置 2026-2027 法定节假日，可手改

## 6. 前端形态

- 孩子端：宠物舞台（居中大区域，精灵 + 动画 + 粒子）+ 今日任务卡片列表 + 宠物对话气泡。**iPad 横屏优先**，PWA（`manifest` + service worker），Safari"加到主屏幕"后全屏运行、有图标，体验接近原生。
- 家长端：移动端优先的配置/确认/看板，风格从简（不用像素风，加载快）。
- 摄像头/录音/计时：Web 标准 API（`getUserMedia` / `MediaRecorder`），iPad Safari 支持良好。
- 技术：P0 原生 HTML/CSS/JS + 静态精灵 + CSS 动画；P1 用 pixi.js 重做宠物舞台（hi-bit 高清像素 + bloom 光效 + 粒子）。素材 itch.io 像素宠物包起步。
- 对话 SSE 流式输出。
- **跨端平移策略**：Go 后端 REST API 与前端严格分离、API 前端无关。将来若需原生 App（推送等），可用 Kuikly（Kotlin，腾讯开源免费，六端）/ Flutter 重写客户端，后端零改动。当前阶段不引入跨端框架——Kuikly 面向客户端 App 跨端（iOS 打包需苹果开发者账号 $99/年，H5/小程序端为 Beta），Web/PWA 已满足 iPad 场景且与 NAS 部署天然匹配。

## 7. 技术架构

- Go 单体（gin/chi），SQLite 单文件，嵌入式静态资源，单二进制部署
- 模块：任务引擎（物化 cron）/ 奖励引擎（结算+连击）/ 宠物状态机（数值衰减定时任务）/ LLM 网关（最薄 provider 抽象 + 安全过滤 + 限次）
- 部署：P0 期间 WorkBuddy 站点发布（在线链接，家人手机可访问）；稳定后迁 NAS（同一二进制 + SQLite 文件搬走）
